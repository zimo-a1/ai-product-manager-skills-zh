# AI 产品竞品分析

## 目标

为 AI 产品经理生成可用于立项、PRD、汇报和产品决策的竞品分析材料。默认交付一套“决策可用”的分析包：

- 标准竞品分析报告
- 竞品对比矩阵
- 功能清单拆解
- 用户流程图
- 商业模式与定价分析
- AI / 模型 / RAG / 数据能力分析
- PRD 可用机会点与差异化策略

默认使用 Markdown 输出，方便复制到飞书或 Notion。用户要求文件产物，或报告较长时，生成独立文件。

## 输入判断

开始前先判断用户提供的信息类型：

- 只有一个产品名
- 只有一个赛道方向，例如“AI 穿搭助手”
- 一个或多个竞品官网链接
- 截图、录屏、导出的笔记、应用商店页面或产品文档

如果用户只给赛道方向，默认调研 5-8 个代表性竞品。如果用户只给一个产品，必要时补充 3-5 个相近竞品作为参照。如果业务范围不清楚，最多问 3 个澄清问题；如果可以合理假设，就直接推进，并在报告中标注假设。

## 联网调研策略

竞品信息变化快，默认必须联网调研，除非用户明确要求不联网。

资料优先级：

1. 官方网站、产品文档、定价页、博客、更新日志
2. App Store / Google Play / Chrome Web Store / Product Hunt 等页面
3. 公司公告、帮助中心、Release Notes
4. 可信的评测文章、拆解文章、公开演示
5. 社区评论、社交平台反馈只作为辅助信号

报告中的关键事实要附来源链接。必须区分“有来源的事实”和“基于资料的推断”。

## 工作流程

1. **定义赛道**
   - 明确品类、目标用户、核心任务、使用场景和购买/使用触发点。
   - 如果用户输入较宽泛，先写明分析假设。

2. **选择竞品**
   - 包含直接竞品、相邻替代品和新兴 AI 原生产品。
   - 说明每个竞品被纳入分析的原因。

3. **收集事实**
   - 产品定位与价值主张
   - 目标用户与核心场景
   - 核心功能
   - AI 能力、模型使用、多模态能力、自动化深度
   - RAG / 数据 / 知识库能力
   - 用户流程与新手引导
   - 商业模式、定价与权益包装
   - 增长获客渠道
   - UI / 交互观察

4. **对比分析**
   - 使用表格化对比矩阵呈现差异。
   - 标出行业标配功能、真正差异点、薄弱点和市场空白。
   - 对 AI 产品要判断：AI 是核心工作流自动化，还是只停留在表层生成。

5. **推导产品机会**
   - 把竞品发现转化成 PRD 可用机会点。
   - 按用户价值、实现可行性、数据/模型难度、商业影响进行优先级判断。
   - 明确“可以借鉴什么”“应该避开什么”“我们在哪里差异化”。

6. **组织交付物**
   - 先给简短、明确的结论。
   - 再输出详细报告、对比矩阵、流程图和 PRD 机会点。
   - 最后补充风险、未知项和下一步调研建议。

## AI 产品分析维度

除非明显无关，默认覆盖以下维度：

- 产品定位
- 目标用户
- 核心场景
- 功能架构
- 用户流程
- AI / 模型能力
- RAG / 数据能力
- 商业模式
- 定价
- 增长获客
- UI / 交互
- 优劣势
- 可借鉴点与差异化机会

分析 AI / 模型能力时重点看：

- 输入模态：文本、图片、音频、视频、文档、网页
- 输出模态：文本、图片、音频、视频、工作流动作
- 自动化深度：建议、Copilot、Agent 执行、后台自动工作流
- 个性化能力：用户记忆、工作区上下文、行为数据
- 集成方式：浏览器、App、API、插件、MCP/工具、第三方应用
- 可信机制：引用来源、事实 grounding、评估机制、安全护栏

分析 RAG / 数据能力时重点看：

- 数据来源与导入方式
- 解析与清洗能力
- Chunk 切分与索引方式
- 检索范围与排序逻辑
- 引用来源展示
- 用户私有知识处理
- 反馈闭环与记忆机制

## Mermaid 图表

以下内容优先用 Mermaid 表达：

- 用户注册、上传、生成、付费等核心流程
- RAG / 数据处理链路
- AI Agent 工作流
- 产品架构或功能模块关系

图要保持可读。如果一张图过于拥挤，拆成多张图。

## 质量标准

最终输出前检查：

- 关键事实是否有来源。
- 是否把推断误写成事实。
- 是否提供了信息来源链接。
- 是否把观察转化成产品启发。
- 机会点是否足够具体，能进入 PRD。
- 结论先行是否短、准、能支持决策。

## 信息缺失时

如果找不到某个竞品信息，要明确写出：

- 没找到什么
- 为什么这个信息重要
- 基于现有信息的合理推断，并标注“推断”
- 下一步如何验证
